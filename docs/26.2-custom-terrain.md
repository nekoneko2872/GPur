# GPur 26.2 カスタム地形

[日本語](26.2-custom-terrain.md) | [English](26.2-custom-terrain.en.md)

GPur 1.1.0では、新しく作成するオーバーワールドに対して、ワールド単位で選択できるバージョン付き地形生成を追加しました。ほかのワールドのバニラ生成は変更しません。このページは実装されたコードの説明であり、新たな実機試験や性能検証の記録ではありません。

1.1.0の起動用JAR: `gpur-server/build/libs/gpur-server-26.2-SNAPSHOT1.1.0.jar`。

## 新しいワールドで有効にする

`bukkit.yml`の`worlds`設定は、その名前のワールドにgeneratorを割り当てるだけで、ワールドの作成や既存ワールドの変換は行いません。現在のメインワールドは、引き続きCPU上のバニラ地形を使います。既存ワールド名にgeneratorを追加しても、保存済みチャンクは変換されません。既存のワールドディレクトリはそのまま残し、未使用の新しい名前を選んでください。

新しいワールドをサーバーのメインワールドにする場合は、まず`server.properties`の名前を未使用の名前に設定します。

```properties
level-name=gpur_world
```

その後、サーバーを起動する前に`bukkit.yml`へ同じ名前の`worlds.gpur_world`を設定します。

```yaml
worlds:
  gpur_world:
    generator: gpur:terrain-v1
```

または、対応する`worlds.<名前>.generator`を設定して、ワールド管理プラグインから別の生成器を指定せずに新しいNORMALワールドを作成してください。`WorldCreator.generator(String)`のプラグイン名による解決では、この組み込み生成器IDを直接指定できません。既存ワールドを変換するためにこの設定を使わないでください。

ワールドの環境はNORMALで、`chunk-generation.custom-terrain.enabled`を`true`にする必要があります。この設定は新規ワールドでの選択を許可しますが、それだけでワールドを切り替えることはありません。初回の有効化時に既存の`.mca`または`.mcc`チャンクデータが見つかったワールドは拒否します。既存の未マークワールドが自動的に切り替わることはありません。ネザーとエンドは従来のCPU生成を維持します。これらの環境で`gpur:terrain-v1`を明示選択した場合は拒否します。

ワールド情報の初回検証時に、チャンクを生成する前に`gpur-terrain.properties`を原子的に保存します。マーカーにはスキーマと地形ルールのバージョン、シード、最小Y、高さ、海面を記録します。これらはマークされたワールドで固定です。次回以降の読み込みでは、シードや高さの設定変更、不正・未対応のマーカー、別のgenerator指定を拒否します。後から`bukkit.yml`のgenerator指定を削除しても、GPurはマーカーを検出してカスタム生成器を復元します。GPU計算の停止やシードの再生成を目的にマーカーを削除・編集しないでください。マーカーはワールドの地形仕様を保持します。GPU計算が無効・利用不可・タイムアウト・照合失敗の場合も、マークされたワールドでは同じカスタムCPUルールを使います。

## GPUの利用条件と設定

ワールドの選択、カスタム地形の有効化、GPUの準備状態は別々の条件です。ワールド設定がカスタム地形を選択し、`chunk-generation.custom-terrain.enabled`が新規ワールドでの選択と地形スケジューラを有効にします。GPU計算には、全体のGPUアクセラレーションと旧キー`chunk-generation.gpu-acceleration.terrain-enabled`も必要です。旧名に`terrain-enabled`とありますが、これは明示選択されたカスタム生成器のGPU計算を制御するキーです。バニラ地形をGPUへ移すものではありません。いずれかのGPU設定を無効にしても、マーク済みワールドは同じカスタムCPUルールで生成します。

カスタム地形の既定値と関連するGPU設定です。

```yaml
gpu:
  cache:
    enabled: true
  multi-gpu:
    enabled: true
    devices: [auto]
chunk-generation:
  gpu-acceleration:
    enabled: true
    terrain-enabled: true
  custom-terrain:
    enabled: true
    auto-tune: true
    max-batch-chunks: 8
    queue-capacity: 128
    batch-wait-ms: 2
    request-timeout-ms: 250
    parity-interval: 128
```

`gpu.multi-gpu.devices`には`auto`、起動ログに表示されるGPUのUUID、または正確なデバイス名を指定できます。GTX 1080だけを選ぶには、起動ログの正確な名前を使って複数GPUを無効にします。

```yaml
gpu:
  multi-gpu:
    enabled: false
    devices: [NVIDIA GeForce GTX 1080]
```

設定したGPUが利用できない、または利用審査を通らない場合は、CPU参照ルールで地形を生成します。GPUを設定しただけでは地形処理は発生しません。`gpur:terrain-v1`を選択したワールドで新規チャンクを生成するときだけ処理を投入するため、新しいカスタム地形をほとんど生成していない時間帯にGPU使用率が低いのは正常です。

`auto-tune: true`では、各GPUについて`max-batch-chunks`以下の1・2・4・8チャンクからバッチサイズを選びます。新規のチューニング情報がない場合、GPUごとに最大16回の範囲を絞った調整ディスパッチを行い、CPU/GPUの同一結果も検査します。互換性のある保存済み情報も起動時に再検査します。地形計算の結果は定期的に照合し、間隔は`parity-interval`で設定します（既定は128ディスパッチごと）。`gpu.cache.enabled`はVulkanパイプラインと地形バッチ設定の永続キャッシュを制御します。キャッシュ識別情報には物理GPU、ドライバー、シェーダー、地形ルールのバージョンを含みます。一致しない情報は再利用せず、作り直します。これは上限付きの決定的な調整であり、AI学習モデルではありません。

実行時の状態表示では、GPUごとの受理済みディスパッチに含まれるチャンク数、CPU退避理由、選択したバッチサイズを確認できます。全体の`Custom terrain returned`は地形スケジューラが呼び出し元へ返したパレット数をGPU/CPU別に数えます。GPUごとの受理済みディスパッチ数には、呼び出し元がタイムアウトしてCPUパレットを受け取ったチャンクが含まれる場合があります。プライマリスレッドのCPU生成はスケジューラを通らないため、これらのカウンターには含まれません。カウンターはスケジューラの処理状況であり、GPU使用率や高速化を保証する数値ではありません。

## GPUとCPUの処理範囲

GPUカーネルは、地表のブロック、水、洞窟、溶岩を含むカスタム地形の決定的なブロックパレットを計算します。Bukkitアダプターはgeneratorコールバック上でCPUを使ってチャンクデータへ反映します。バイオーム参照と基準高度の問い合わせも同じルールをCPUで計算します。バニラの構造物・装飾（鉱石を含む）、ライティング、チャンクの直列化・保存、Mob AI、レッドストーン、プラグインコールバック、ワールド更新はCPU処理です。保存には既存のPaper/Minecraftのチャンク保存経路を使います。この変更で保存性能が向上するとは主張しません。

Bukkit標準のチャンク生成器・バイオームプロバイダーAPIを使いますが、すべてのプラグインとの互換性を証明するものではありません。この機能のための新たなGPU実機試験やサーバー全体の性能試験は行っていません。過去の1.0.0実機・負荷記録は、記録対象のビルドと負荷条件についての測定として引き続き有効です。ただし、1.1.0のカスタム地形経路は測定していません。この機能の対応ハードウェア認定や性能向上は主張しません。

[1.1.0のコード検証記録](results/1.1.0-code-validation.json)では、パッチ適用とJDK 25でのビルドが成功し、9,334件のテストで失敗・エラー0件、スキップ26件でした。シェーダーはCPU上でSPIR-Vへコンパイルしました。地形の連続性と素材、待ち行列と終了処理、永続ワールド情報、キャッシュ検査とチューニング情報の保存、状態表示をテストしています。新しい経路のGPU実行とサーバー全体の高速化は未検証です。

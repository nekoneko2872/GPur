# World generation development toward 2.0.0

[日本語](2.0.0-development.md)

This is a development record. The product version remains **1.1.0**. It does not establish a completed 2.0.0 implementation or an end-to-end speedup. The version will not advance until every requested stage and validation gate is complete.

## Implementation boundaries

The existing generator, seed initialization and arithmetic order remain authoritative. These paths use no approximation or quantization. Paper events, world mutation and disk writes remain on the CPU.

| Stage | Added path | Remaining work |
| --- | --- | --- |
| Noise | FP64 Improved, Perlin, Normal and Blended noise batches. The original CPU graph uses a cached value only when sampler identity and every input-coordinate bit match | Density graph arithmetic, splines, dynamic ShiftedNoise terminal inputs, unsupported nodes and existing graph/cache control |
| Interpolation | The exact asynchronous 1.1.0 path continues | Original CPU interpolation on rejected GPU work |
| Aquifer | GPU selection of the nearest four candidates from CPU-initialized center coordinates, preserving the original iteration and tie order | Fluid status, pressure, surface queries and fluid-update decisions |
| Surface, structures and decorations | Existing CPU paths retained | GPU computation has not been implemented |
| Block placement | Original CPU loop and commit retained | Compact final block-classification readback has not been implemented |
| Lighting | Existing CPU path retained | GPU computation has not been implemented |
| Saving | Existing CPU path retained | GPU NBT serialization/compression has not been implemented; disk writes will remain on the CPU |

The new boundaries have separate validation opt-ins, disabled by default:

```yaml
chunk-generation:
  vanilla-terrain:
    mode: strict
    noise-batches: true
    aquifer-ranking: true
```

`strict` compares every GPU result with the CPU reference. After strict correctness and saved-world parity pass, performance uses separate fresh-world `verified-exact` runs. A run that repeats every GPU calculation on the CPU is not a speedup measurement.

## Correctness and lifetime

Only copied numerical snapshots cross the device boundary. Seeded noise initialization and positional aquifer randomness use the original CPU implementation. Aquifer ranking retains the original X/Y/Z visit order and `>=` tie insertion.

Result lifetimes and retained CPU bytes are bounded. Shutdown, cancellation and generation changes reject stale results. A Java readback array is never recycled during a CPU read. Interpolation cancellation is serialized with block mutation so sections cannot be released during consumption.

The service also tracks enclosing chunk futures, so an executor that accepts and later drops a continuation cannot strand its section leases at shutdown. Live configuration reload retires GPU results while admitted chunk owners finish on the CPU. Retired services remain reachable until setup scopes and owners drain; server shutdown cancels any remaining owners after chunk tickets are deactivated. Only cancellation from a GPur NOISE continuation uses the scheduler's ordinary cancellation result; real generation failures keep their original failure handling.

The request collector visits only known vanilla nodes. It does not evaluate or rewrite arbitrary plugin/custom nodes, replace the live density graph, or introduce a different terrain generator.

## Validation and release decision

A GPT-6 Luna agent at xhigh reasoning performs validation. Kernel parity alone does not complete the release.

- Compare the original CPU implementation on GTX 1080, RTX 3070 and mixed GPUs.
- Record returned results and actual consumption by the original generator separately.
- Use fresh worlds with identical seeds and coordinate lists; compare blocks, biomes, heightmaps, lighting, structures and fluid-related data.
- Compare persisted data after save, clean shutdown, restart and reload.
- Repeat the 1.0.0 player movement, mob, redstone and exploration scenarios on the candidate JAR.
- Establish performance at least equivalent to the CPU and leave the version unchanged while requested stages or tests remain incomplete.

See the [isolated harness](../benchmarks/worldgen/README.md) and [release gate](../benchmarks/worldgen/release-gate.json). Confirmed execution results will be added after the runs finish.

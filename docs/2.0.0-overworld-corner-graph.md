# Stage 7 candidate: Overworld corner-density graph

This is a read-only source audit and implementation proposal. It does not add a kernel or claim that GPur currently evaluates density graphs on the GPU.

## Why this is a useful bounded stage

The Overworld `finalDensity` is assembled in `NoiseRouterData.overworld` as `min(postProcess(slideOverworld(caves)), NOODLE)`. `postProcess` places an interpolated marker around `mul(blendDensity(slide), 0.64)` and applies `squeeze` after interpolation. The marker's `noiseFiller` is the expensive corner function that `NoiseChunk.fillSlice` currently evaluates on the CPU. It includes the terrain splines, shifted climate noises, cave choices, slides, and noise leaves. Workload 5 precomputes noise values but still walks this graph on the CPU at each corner.

For a fresh world, `Blender.empty()` makes `NoiseChunk.wrapNew` unwrap the `BlendDensity` marker. That leaves this root as a pure vanilla density graph. A new chunk path can compile each supported `NoiseInterpolator.noiseFiller` to immutable instructions, return only the root values for its corner lattice, and copy those values into the existing slices. Workload 4 then keeps its current interpolation behavior. This removes CPU evaluation of the corner graph while leaving per-block density combination, aquifer classification, ore rules, and all chunk writes on their current owner thread.

Chunks that blend old and new generation have a `NoiseChunk.BlendDensity` wrapper whose output depends on `Blender` data. The first graph stage should reject that interpolator root and use the existing CPU path for it. Rejection should be per root so that independent supported roots can still run on the device.

## Exact default-Overworld closure

The source-built Overworld router creates eight interpolator roots: the main post-process root; four roots used by the noodle toggle, thickness, and two ridges; the ore-vein toggle; and the two ore-vein ridges. The root compiler needs the following exact operators to cover those roots on the ordinary vanilla graph:

- constants, `BlendAlpha` and `BlendOffset` (the latter two evaluate to 1 and 0 in the empty-blender case), Y-clamped gradients, clamps, `Mapped`, `MulOrAdd`, and two-argument add/multiply/min/max;
- `RangeChoice` and `IntervalSelect`, including their strict boundary comparisons and lazy branch selection;
- `Noise`, `Shift`, `ShiftA`, `ShiftB`, and `ShiftedNoise`, including dynamic shifted coordinates;
- nested `DensityFunctions.Spline` values, with coordinate functions and every spline interpolation intermediate kept in Java's binary32 order;
- `BlendedNoise` and resolved holder nodes;
- `FlatCache` at its cached Y=0 coordinate; `Cache2D` only when its child is proven Y-independent; and `CacheOnce` with explicit cache invalidation described below.

`FindTopSurface` and `EndIslandDensityFunction` are not in the ordinary Overworld interpolation roots. A plugin-provided density node, an unknown node class, an active blender wrapper, or a dimension whose root includes an unsupported node rejects only that root. Do not lower an unknown subtree as a constant or return a partial result to the live graph.

The exporter must snapshot the already-wrapped graph without invoking the replacing visitor used by `NoiseChunk.wrap`, which creates mutable runtime caches and interpolators. Assign IDs by object identity so shared vanilla nodes and noise profiles remain shared. Keep child evaluation order and short-circuit rules in the bytecode; do not algebraically fold, reassociate, or eagerly execute conditional branches. The shader receives only bounded primitive instructions, immutable noise profiles, integer corner coordinates, and returns one raw binary64 value per compiled root and corner. It receives no `NoiseChunk`, world, `Blender`, `ChunkAccess`, block state, or random source.

Direct slice filling must also account for CPU cache side effects. The current leaf-noise cache still invokes the original `fillArray`, so it does not introduce this issue. `sliceFillingContextProvider.forIndex` and `fillAllDirectly` increment `NoiseChunk.interpolationCounter`; different density `fillArray` implementations invoke these callbacks a different number of times. `CacheOnce.compute` uses that counter and `arrayInterpolationCounter` as cache keys. On a fresh chunk, `initializeForFirstCellX` resets `interpolationCounter` to zero and `CacheOnce.lastCounter` also starts at zero, so skipping the corner callbacks can make the first later CPU cell evaluation treat the default cached scalar as a hit. `CacheOnce.fillArray` also fills `lastArray` for reuse within an array epoch.

One possible guard is to collect the exact reachable `NoiseChunk.CacheOnce` wrappers and clear their scalar and array memo state after GPU values are installed. This audit does not establish that invalidation as safe. Before enabling it, test all original counter consumers, array-cache sharing across roots, and the first `selectCellYZ` plus per-block reads against an untouched CPU `NoiseChunk`, including wrappers shared between roots. If those effects cannot be proven equivalent for a whitelisted graph, keep the original root `fillArray`; reject roots containing custom or unsupported child nodes. `CacheAllInCell` and nested interpolators are outside this stage. Preserve the original fill-array context for every CPU root that is not actually bypassed.

`Cache2D.fillArray` delegates to its wrapped function, while `Cache2D.compute` updates position/value state. Treat it as transparent only after proving its child does not depend on Y; otherwise reject the root. `FlatCache` has different semantics: its fill path reads a precomputed X/Z table made by evaluating the wrapped function at Y=0. Lower it with Y fixed at zero in the empty-blender case. Do not attempt to preserve caches by adding an arbitrary counter increment: cache callbacks are branch-dependent, and that would not reproduce the values or shared-cache state.

## Integration and bounds

Add a dedicated versioned density workload and immutable result owner. Bound node count, edges, maximum interpreter work (`instructionCount * cornerCount`), profile words, root count, output words, and total retained bytes before dispatch. Enable direct slice filling only when a result is still usable and its exact root identity and corner coordinates match. A miss, stale result, unsupported graph, or admission refusal calls the original `fillArray` for that root.

Reuse the existing async continuation and result-lease pattern: create primitive snapshots on the serial owner, prepare the device future, install completed values before slice initialization, consume them only while the same `NoiseChunk` remains serially owned, then release the frame in normal cleanup or cancellation. A compiled root must bypass its complete CPU `fillArray`; recording only GPU noise-leaf consumption does not count as graph work removed.

Expose counts for roots examined, compiled, CPU-fallback by node class/reason, corner values submitted/accepted/consumed, and graph dispatches. Keep these separate from workload 5 noise-leaf counts so the measured CPU savings correspond to values that actually filled slices.

## Required parity fixture

Construct the regular vanilla Overworld router with a fixed seed and `Blender.empty()`, then obtain the actual `NoiseInterpolator.noiseFiller` roots after `NoiseChunk` wrapping. At negative and positive chunk coordinates, compare every compiled corner result against the unmodified `fillArray` path by raw `Double.doubleToRawLongBits`. Include all eight roots, negative and boundary Y values, shifted-noise coordinates, spline knot neighborhoods, interval and range-choice thresholds, shared node identities, and caves enabled. Then run the first `selectCellYZ` and per-block CPU evaluation with the installed GPU slices; compare results against an untouched CPU `NoiseChunk`, especially for a `CacheOnce` shared across roots. Compare the resulting slice arrays before allowing workload 4 to consume them.

Run the same fixture through the hardware shader path and exact startup corpus. Add fail-closed fixtures for a nonempty blender, an unknown density node, and an unsupported dimension root; each must show the original CPU root result and zero graph values consumed for that root. Extend async lifecycle coverage for cancellation, device quarantine, stale leases, and cleanup of a completed graph frame. No server build or tests were run for this audit.

## Source anchors

The current behavior is in the generated vanilla `NoiseChunk` source: `fillSlice`, `sliceFillingContextProvider`, `initializeForFirstCellX`, `selectCellYZ`, `updateForZ`, `CacheOnce`, `Cache2D`, and `NoiseInterpolator.fillArray` / `selectCellYZ`. The corresponding GPur hooks are in `gpur-server/minecraft-patches/sources/net/minecraft/world/level/levelgen/NoiseChunk.java.patch`; static leaf collection is in `DensityFunctions.java.patch` (`gpurCollectStaticNoise`). The root shapes and eight interpolator-bearing definitions are in generated `NoiseRouterData.overworld`, `noodle`, and `postProcess`.

# 2.0.0 に向けた生成経路の開発記録

[English](2.0.0-development.en.md)

これは開発中の記録です。製品バージョンは **1.1.0** のままで、2.0.0 の完成・性能向上を示すものではありません。要求された全工程の実装と検証が完了するまで、2.0.0 へ更新しません。

## 実装の境界

既存の生成器、seed、ノイズの初期化、演算順序を維持します。近似や量子化は使用しません。Paper のイベントとワールドへの変更確定、ディスクへの書込みはCPUに残します。

| 工程 | 今回追加した経路 | 残っている処理 |
| --- | --- | --- |
| ノイズ | Improved / Perlin / Normal / Blended のFP64バッチ計算。既存グラフの静的なノイズ入力を収集し、同じサンプラーと座標ビットが一致する結果だけを元のCPUグラフが使用 | 密度グラフの演算、Spline、動的ShiftedNoiseの終端、非対応ノード、グラフや既存キャッシュの制御 |
| 補間 | 1.1.0 の厳密な非同期補間を継続 | GPU受付失敗時は元のCPU補間 |
| 帯水層 | CPUで初期化済みの中心座標をGPUへ送り、元のループと同じ上位4候補を選択 | 流体状態、圧力、地表参照、流体更新フラグの判定 |
| 地表・構造物・装飾 | 既存のCPU経路を維持 | 計算のGPU移植は未実装 |
| ブロック配置 | 元のCPUループ・変更確定を維持 | GPUから確定ブロック分類を一括受信する経路は未実装 |
| 照明 | 既存のCPU経路を維持 | GPU移植は未実装 |
| 保存 | 既存のCPU経路を維持 | NBT直列化・圧縮のGPU移植は未実装。ディスク書込みはCPUを維持する方針 |

新しい境界は検証用の独立した設定です。既定値は無効です。

```yaml
chunk-generation:
  vanilla-terrain:
    mode: strict
    noise-batches: true
    aquifer-ranking: true
```

`strict` はGPU結果をCPUで全量照合します。性能比較には、厳密照合とワールド一致を確認した後、別の新規ワールドで `verified-exact` を使用します。常時全量照合した実行の速度を、そのままGPU化による速度向上として扱いません。

## 品質の条件

GPUスレッドへ渡すのは数値のコピーだけです。ノイズの乱数初期化と帯水層の位置乱数は元のCPU実装を使用します。帯水層の同距離候補は、元のX/Y/Z訪問順と `>=` の挿入順を維持します。

GPU結果の寿命とCPU側の保持容量を管理し、停止・キャンセル・世代更新時には結果を採用しません。GPU用の配列はCPU操作中の読取りで再利用されません。補間のキャンセルと変更確定を直列化し、処理中にセクションを解放しないようにしています。

ノイズ収集は既知のバニラノードだけを訪問します。未知のプラグイン・カスタムノードを評価・書換えません。元のキャッシュや密度グラフを別の生成ルールへ置換しません。

設定の再読み込みでは、古いGPU結果を無効にして、既に開始したチャンクの生成をCPU側で完了させます。停止時にはチャンクの生成要求を止めてから、外側の生成futureをキャンセルします。これにより、受理済みの実行待ち処理をキューが破棄しても、チャンクの所有権と数値結果を解放できます。GPurのNOISE処理のキャンセルだけをスケジューラの通常キャンセルとして扱い、実際の生成エラーは元のエラー処理へ渡します。

## 検証とリリース判定

検証はGPT-6 Luna・xhighの担当エージェントが実行します。カーネルの一致だけでは完成と判定しません。

- GTX 1080、RTX 3070、混在GPUで、元のCPU実装との結果一致を確認する。
- GPU結果の完了数と、元の生成処理が実際に使用した数を別々に記録する。
- 同じseed・座標列の新規ワールドを使い、ブロック、バイオーム、高さ、照明、構造物、流体関連データを比較する。
- 保存、正常終了、再起動、再読込後にも保存データを比較する。
- 1.0.0で実施したプレイヤー移動、Mob、レッドストーン、探索の負荷試験を候補JARで再実行する。
- CPUと同等以上の性能を検証し、未移植の工程と未実行の試験を残したまま2.0.0を公開しない。

詳細は[隔離検証ハーネス](../benchmarks/worldgen/README.md)、[リリースゲート](../benchmarks/worldgen/release-gate.json)、[検証記録JSON](results/2.0.0-development-validation.json)を参照してください。

## 初回の実ワールド試験：失敗

新規ワールド・半径4のstrict試験（`20261009T144307Z-d686916b`、各構成81チャンク、ヒープ16 GiB）は4構成とも失敗しました。RTX 3070とGTX 1080では、ワールド作成中にworkload 6がCPU参照値と不一致になりました。どちらもdispatch 1回・照合1回・採用0回です。混在構成でも両GPUで同じ境界の不一致が発生しました。結果を破棄してGPU採用を停止したため、後続のworkload 5が実行不可となっています。小さい入力のカーネル検証だけでは、本番サイズの入力の正常動作を証明できませんでした。

CPU構成は81チャンクを生成・保存しましたが、比較ツールがワールドのブロック範囲外にある照明専用セクションを誤って拒否しました。この判定を修正しました。また、PaperはStarlightのバージョン情報とともに意図的に`isLightOn=false`を保存するため、照明の有効性はPaperの読込条件に従って判定します。比較ツールの修正によって失敗した試験を合格には変更しません。保存地形の一致・再起動比較・性能比較・移動試験の再実行は、まだ立証できていません。バージョンは1.1.0のままです。

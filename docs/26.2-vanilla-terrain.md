# GPur 26.2 バニラ地形ノイズ補間

[日本語](26.2-vanilla-terrain.md) | [English](26.2-vanilla-terrain.en.md)

GPur 1.1.0には、既存のバニラ地形生成器にあるノイズ補間段階だけを対象にした、範囲を制限したVulkan経路があります。初期値は無効です。この文書はコードの範囲を説明するもので、新たな実機試験やサーバー全体の性能検証を示すものではありません。

1.1.0のサーバーJAR: `gpur-server/build/libs/gpur-server-26.2-SNAPSHOT1.1.0.jar`。

## GPUで処理する範囲

Paper/Purpur標準のバニラ生成器をそのまま使います。`bukkit.yml`のgenerator設定や新しいワールドは不要です。既存のワールドディレクトリ、保存済みチャンク、シード、データパック、保存形式を置き換えません。この設定を有効にしてもバニラの生成ルールは維持され、GPU経路の対象は範囲を制限したノイズ密度の補間処理だけです。

CPUがバニラの密度グラフを組み立て、実際の角の密度値を計算します。GPUはそれらの値を入力として、FP64とCPUと同じ演算順序で、範囲を制限したスラブ内を補間できます。厳密検証が有効な場合は、GPUの各バッチをそのスラブ全体のCPU参照結果と比較します。GPUがチャンク全体を生成するわけではありません。

密度・ノイズグラフの構築、乱数生成、ブレンディング、アクアファイア、地表ルール、洞窟、バイオーム、構造物、ブロック配置、ライティング、チャンクの直列化と保存はCPU側に残ります。装飾・構造物・ワールドへの変更も、通常のPaper/Purpur経路で処理します。実際の処理量は既存のワールド生成負荷によって変わり、このリリースで生成速度や範囲を保証するものではありません。

## 設定

この機能の初期値は`false`です。GPUを使用するには、全体のGPUアクセラレーション設定と既存の地形GPU設定も有効である必要があります。デバイスは既存の`gpu.multi-gpu.devices`で選択します。

```yaml
gpu:
  multi-gpu:
    enabled: true
    devices: [auto]
chunk-generation:
  gpu-acceleration:
    enabled: true
    terrain-enabled: true
  vanilla-terrain:
    enabled: false
    verify-every-batch: true
    max-interpolators: 16
    max-slab-values: 1048576
    minimum-values: 1024
    parity-interval: 128
```

バニラ補間経路を選ぶには`chunk-generation.vanilla-terrain.enabled: true`だけを設定します。generatorの選択やワールド作成の変更は不要です。`max-interpolators`と`max-slab-values`は受け付ける処理量の上限です。1,024値未満のスラブはCPUで処理します。既定の`verify-every-batch: true`は厳密モードで、すべてのバッチをCPU参照と照合します。`parity-interval`は`verify-every-batch`を`false`にした場合だけ使われます。制御された診断以外では厳密検証を有効のままにしてください。この経路は性能検証されていないため、検証を無効にしたり`gpu.force: true`を設定したりすることを高速化の方法として勧めません。

デバイスは`auto`、起動時に表示されるUUID、または正確なデバイス名で選択できます。次の例は表示名でGTX 1080だけを選びます。この指定は選択方法の例であり、この地形経路の性能を認定するものではありません。

```yaml
gpu:
  multi-gpu:
    enabled: false
    devices: [NVIDIA GeForce GTX 1080]
```

GPUの利用可否、照合結果、処理量によってGPU処理が採用されるかが決まります。デバイスを設定しただけ、またはアイドル状態のGPUがあるだけでは、地形処理がGPUに投入されたことを意味しません。実行コンテキストの占有率もGPUハードウェア使用率ではありません。起動ログと`/gpur status`で、実行時の準備状態や表示可能な処理数を確認してください。

## 先読み設定は別のCPU負荷調整

`chunk-generation.preloading.max-extra-distance`の初期値は`0`です。`2`にすると全方向の先読み範囲が広がり、CPUのチャンク読み込み・生成・送信負荷が増える場合があります。GPU補間を有効にする設定でも、バニラ地形ルールを変更する設定でもありません。

高性能サーバーでは、エリトラ飛行中の生成並列数を増やすCPU負荷設定を任意で有効にできます。

```yaml
chunk-generation:
  preloading:
    max-extra-distance: 2
    elytra-throughput-boost:
      enabled: true
      max-extra-concurrent-generates: 8
      concurrent-generates-multiplier: 2.0
```

このブーストは初期値では無効で、プレイヤーが実際にエリトラ飛行している間だけ適用されます。倍率の初期値`2.0`では、Paperが自動または明示設定から解決した基準並列数に対し、次の数だけ生成枠を追加します。`min(ceil(基準値 × (倍率 − 1)), max-extra-concurrent-generates)`。加算結果は整数の最大値で飽和し、Paperの`-1`（無制限）はそのまま維持します。上限の初期値は`8`で、設定範囲は`0..64`です。この並列数設定は`generate-rate-multiplier`とは別です。後者は生成要求のレートを変えます。並列数の設定は対象チャンクを遠くまで選びません。選択範囲を広げるのは`max-extra-distance`です。どちらの設定もCPU負荷を増やす場合があり、TPSを保証しません。バニラ地形ルールは変更せず、GPU補間も有効にしません。

## カスタム生成器は新規選択不可

マーカーのないワールドに`gpur:terrain-v1`を新しく設定する方式は廃止され、起動時に理由を示して失敗します。バニラ地形を使うには、そのgenerator設定を削除するか、`server.properties`の`level-name`を読み込みたい既存のバニラワールドディレクトリ名に戻します。たとえば、`gpur`という名前の既存ディレクトリを読み込む場合は次のようにします。

```properties
level-name=gpur
```

`bukkit.yml`に`worlds.gpur.generator`があれば、その該当設定を削除します。ワールドディレクトリやマーカーファイルは削除しないでください。`gpur-terrain.properties`があるワールドは、過去のカスタム地形ワールドとして扱われます。GPU地形を無効にしても、GPurはそのワールドの既存ルールに合わせて従来のカスタムCPU生成器を復元します。マーカーを削除・編集してバニラに変換しないでください。

旧設定`chunk-generation.custom-terrain.enabled`は、ワールドを選択せず、バニラ補間経路も有効にしません。このページの範囲を制限したバニラ経路には`chunk-generation.vanilla-terrain.enabled`を使用します。

## 検証範囲

過去の1.0.0実機・負荷記録は、記録されたビルドと負荷条件についての測定として引き続き有効です。1.1.0のバニラ地形ノイズ補間経路を測定した記録ではありません。この機能に新たな実機認定や性能向上の主張はなく、GPU処理は実験的かつ範囲を制限したものです。

[今回のコード検証記録](results/1.1.0-vanilla-code-validation.json)では、パッチ適用とビルドが成功し、9,346件のテストで失敗・エラー0件、スキップ26件でした。実際のバニラ`NoiseChunk`へCPU参照スラブを注入し、負の座標とワールド境界付近で密度のビット列、ブロック、液体更新判定、終了処理の一致を確認しています。GPU実機の結果や、装飾・保存まで含むワールド全体の比較を測定した試験ではありません。

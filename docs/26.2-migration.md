# GPur 26.2 移行・検証記録

Purpur 26.2をベースに、既存のGPur設定を読み込めるVulkan計算基盤を実装した。プラグイン、イベント、乱数、ワールドへの変更確定はCPU上で実行する。

**Mob AI・レッドストーン・プレイヤー処理全体のGPU移行は未実装。GPU再試行と結果採用の修正前に行った300人全員の同時移動試験では、CPU・3070・1080・混在の全構成でtick停止を検出した。最終試験でも常時TPS安定とCPU構成に対する同等以上の性能は立証できていない。** 以下の検証は、実装した限定的な計算経路と互換性のサンプルを対象にする。

## 実装範囲

| 対象 | 現在の処理 |
| --- | --- |
| 最近傍プレイヤー検索・自然スポーンのプレイヤー距離 | FP64の座標スナップショットをGPUに渡す。演算順序、厳密な範囲比較、同距離の順序を維持。任意のプラグイン述語はCPU経路。 |
| Anti-Xray | PaperのHIDE方式で、6方向の隣接ブロックを考慮した整数マスクをGPU計算。パケット全体を別バッファに書き、定期的に元のPaper処理と全バイトを比較する。 |
| Anti-Xrayのランダム置換方式・特殊な非遮蔽ブロック設定 | 元のPaperのCPU処理。乱数の消費順序を維持する。 |
| Mob AI、プレイヤーの移動・衝突・状態更新、依存するレッドストーン更新 | 元のCPU処理。イベントによるキャンセルや値の変更を維持する。 |
| 地形・構造物生成 | 元のCPU処理。旧GPurのFP32補間・代替地形生成は使用しない。 |
| エリトラ先読み | CPUで移動・視線から優先順位を決める。近距離を優先し、追加のロード範囲を初期値3チャンクに制限。送信・シミュレーション範囲の設定は維持する。 |

GPUが遅い、混雑している、未対応、結果不一致、実行失敗の場合はCPUへ戻す。GPU結果の採用とデバイス無効化・Anti-Xray拒否・サービス終了を同じ短い排他区間で確定し、無効化後に戻った並行要求の結果を採用しない。既に採用を確定した結果の取り消しは行わない。GPU実行、CPU参照計算、ネイティブ資源の終了待ちは排他区間の外で行う。タイムアウトした処理のバッファを他の要求へ再利用しない。Vulkanのホストメモリは、利用可能なら読み取り用のキャッシュを持つ領域を選ぶ。

## 設定の移行

既存の`gpur.yml`はスキーマ2へ移行する。独自キーとカスタム値を保持し、スキーマ1で旧初期値と同じ値の設定だけ次のように修正する。

- `gpu-offload.mob-spawn.min-candidates`: 32 → 1。一度の問い合わせに候補を32個渡す経路が存在しなかったため。
- `gpu-offload.anti-xray.min-sections`: 12 → 1。通常のパケットが閾値に達しない問題を解消する。
- 不正な数値は範囲内に補正し保存する。`allow-inexact-results`は同一挙動を優先するため無効にする。

プレイヤー距離検索の初期値は128人。自然スポーンは32人以上かつ128件以上の距離計算が条件となる。小さな問い合わせは転送費用が大きいためCPUで処理する。これらはGPUを常時稼働させるための設定ではない。

```yaml
gpu:
  multi-gpu:
    enabled: true
    devices: [auto]
  force: false
  timeout-ms: 100
```

`devices`には起動ログに出るUUID、正確なGPU名、`auto`を指定できる。混在GPUは独立したVulkanデバイスとして扱い、SLI/NVLinkを必要としない。`enabled: false`では最初に検証を通過した1台を使用する。

`force: true`は診断用に速度によるCPU優先を解除する。同一結果の検査や安全上の制限は解除しない。通常はディスパッチと読み戻しがCPU計算より遅い場合、該当計算を30秒間CPUへ戻す。期限後の再試行は毎回CPU参照計算と比較し、遅ければ再び30秒待つ。並行した古い比較結果が新しい待機期限を解除しないようCASで更新する。この比較にはスナップショット準備などサーバー全体の費用は含まれない。

旧地形・構造物・リロード保持・スループット安定化・送信バーストの設定キーは移行のために保持するが、これらの旧経路は実行しない。`gpu-usage-fallback`は実行コンテキストの占有率に使い、GPUハードウェアの使用率を示すものではない。PaperのAnti-Xrayを無効にしたワールドでは、GPurが勝手に有効化しない。

Paper・Purpur・プラグインの設定ファイル形式とAPIパッケージは維持する。実際の運用設定やワールドはこの開発用チェックアウトへコピーしていない。

## 検証

検証環境: Windows 11、JDK 25.0.2、LWJGL 3.4.1。

| GPU | 検証 |
| --- | --- |
| NVIDIA GeForce RTX 3070 | FP64境界値、Anti-Xray整数マスク、並行要求、単体・混在構成 |
| NVIDIA GeForce GTX 1080 | 同上 |

Vulkan 1.1、コンピュートキュー、`shaderFloat64`、ホスト可視のcoherentメモリが必要。今回確認した最下位の実機はGTX 1080で、これより古いGPUを最低対応機種として保証していない。起動時にデバイスごとの同一結果検査を行う。

GPur対象のJUnit検査は38件。設定移行、先読み、数値境界、ブランド互換、Anti-Xrayのローカル／グローバルパレット、3ディメンション、隣接チャンクと欠けたセクション、不正GPU結果からの復帰、再試行の待機制御、結果採用と無効化の競合、waypointの反復順序、実機GPUを対象にする。Anti-Xrayでは48パケットの全バイト一致を比較する。GPUテスト4件は明示的に有効にしたときだけ実行する。

GitHub CIと同じ`gradlew build`も成功。全モジュールのJUnit報告は9,831件、失敗・エラー0、スキップ28件だった。この通常ビルドではGPUテスト4件をスキップし、実機GPUを含むGPur対象JUnit検査38件は別の明示的な実行ですべて通している。APIのCheckstyle、Javadoc、禁止呼び出し検査もビルドに含まれる。

`gpur-*`フォルダへの移動後も全buildと実機GPU検査を再確認し、同じ検査件数ですべて通過した。[移動後の検査記録](results/relocated-build-checks.json)を参照。

配布Paperclip JARを隔離したCPU構成とRTX 3070＋GTX 1080構成で起動し、旧設定の読み込み、`gpur status`、`gpur reload`、`version`、正常終了を確認した。Java 21でコンパイルした通常のBukkitプラグインで、ライフサイクル・スケジューラ・イベントのCPUスレッド実行、Mob生成イベントのキャンセル、レッドストーンイベントによる電力7への変更を確認した。全プラグインの互換性を証明する試験ではない。

別途、300人の実TCP接続、3,000体のAI Mob、300個のレッドストーン回路、新規チャンク生成をCPU・3070・1080・混在構成で検証した。全tick、クライアント数・エラー、CPU・メモリ・GC、GPU処理件数を記録している。詳細と失敗した全員移動試験は[負荷検証記録](26.2-validation.md)を参照。通常のPaper/Purpurとの対照試験は行っておらず、サーバー全体の高速化を示す結果ではない。

プレイヤー移動時のwaypointテーブルでは、同じ反復順序を保つ`List.copyOf`にスナップショットを変更し、不要なentryハッシュ計算を除いた。行・列の反復中に要素を削除／置換する検査を追加したが、300人全員の連続移動によるパケット処理の滞留は解決していない。

## 再現手順

JDK 25を使用し、Gitチェックアウトでそれぞれ別のコマンドとして実行する。

```powershell
$env:JAVA_HOME = 'C:\Path\To\jdk-25'
.\gradlew.bat applyAllPatches --console=plain
.\gradlew.bat :purpur-server:test --rerun --tests 'org.gpur.GPurRuntimeTestSuite' --tests 'org.gpur.preload.GPurPreloadTestSuite' -PgpurGpuTests=true :purpur-server:createPaperclipJar --console=plain
.\gradlew.bat build --console=plain
```

GPUのない環境では`-PgpurGpuTests=true`を省略する。生成したMinecraft/Paperソースを変更する場合は、`fixupMinecraftSourcePatches`と`fixupPaperServerFilePatches`の完了後、別のGradle呼び出しで`rebuildAllServerPatches`を実行する。パッチ適用とビルドも別の呼び出しにする。

ソースのフォルダは`gpur-server`・`gpur-api`・`gpur-checkstyle`に移動した。Gradleのプロジェクト名は従来の`:purpur-server`などを維持するため、上のコマンドはそのまま使用できる。公開APIのパッケージ名も維持する。

起動用JAR: `gpur-server/build/libs/gpur-server-26.2-SNAPSHOT1.0.0.jar`。配布名は`gradle.properties`の`mcVersion`（26.2）と`gpurVersion`（SNAPSHOT1.0.0）を組み合わせる。公開APIのバージョンは従来のまま維持する。`-dev.jar`は開発用、`gpur-bundler-*.jar`はビルド中間物。起動時はJDK 25で`--enable-native-access=ALL-UNNAMED`を指定する。

## Gitと配布

ローカルの新しいブランチは`ver/26.2`。上流のコミット履歴、READMEの貢献者・支援者一覧、寄付リンク、IDE設定、旧版の未適用パッチ、未使用の上流テストプラグイン、Purpurロゴの置換パッチを新しいブランチの履歴から除外した。必要な著作権・ライセンス・パッチ由来の表記は保持する。

生成ソース、検証の生ログ、テストワールド、実行用設定、JARはGitに含めず、検証の集計と再現用ツール、ビルドに必要なGradle wrapper JARを含める。既存ブランチとは独立した`ver/26.2`で管理する。

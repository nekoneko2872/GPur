# 動作状況の表示とエリトラ先読みの更新

[日本語](26.2-runtime-updates.md) | [English](26.2-runtime-updates.en.md)

`/gpur status`の表示を整理し、方向先読みの不要な処理を減らした更新です。GPUによる地形生成を追加したものではありません。[大規模負荷の検証記録](26.2-validation.md)は、そこで記録したビルドに対する過去の測定として保持します。

## 状態表示

通常表示ではGPUごとに処理名を並べ、デバイス利用不可・設定による無効・結果未記録・GPU有効・再試行までのCPU退避時間・Anti-Xrayの停止を区別します。色に加えて状態を文字で表示します。「使用可能・待機中」は実際にGPUが計算中という意味ではありません。地形生成とチャンクの方向優先はCPU処理と明記します。

`/gpur status detail`では、ミリ秒単位の時間、CPU参照の照合回数、CPU退避履歴、UUID、GPU受付見送り回数を追加します。ツールチップで意味を確認でき、詳細表示へのリンクからコマンドを実行できます。混在構成の概要サンプルは16行・最長46文字でした。

結果の件数は起動・再読み込み以降に採用したGPU計算バッチ数で、プレイヤー数・tick数・適用済みパケット数ではありません。CPUへの切り替えは計算の投入を試みたものだけを数え、GPU受付見送りもそれ以前のCPU経路をすべて数えるものではありません。どちらも全CPU処理の計測値ではありません。処理中の件数は実行枠の占有数で、GPU使用率ではありません。force指定は速度によるCPU退避を解除しますが、安全上の制限やAnti-Xrayの停止は解除しません。

## 先読みの変更

- 新規設定では方向優先を有効に保ち、`max-extra-distance: 0`、`elytra-throughput-boost.enabled: false`にします。既存の明示的な値は保持します。
- 追加範囲は全方向の読み込み・生成を増やし、飛行時の倍率はCPUの生成要求を最大2倍にしていました。進行方向の優先自体には、どちらの増加も必要ありません。
- 優先度を方向・キュー中心が変わるまでキャッシュします。再構築では、対象キューをすべて空にしてからキャッシュを消します。
- キュー全体より先の距離だけが変わった場合は再構築しません。明示的に有効にした速度倍率には、別に更新した飛行速度を使用します。
- 方向先読みが動作していない場合はPaperの元の比較処理を使用します。

旧設定の`terrain-enabled`でも地形生成はGPUへ移りません。1人接続では通常、距離計算のGPU条件を満たしません。Anti-XrayではGPU計算が発生しますが、照合時にGPU処理が遅ければ一時的にCPUを優先します。

## 検証

Minecraftのファイルパッチ240件、Paperのファイルパッチ42件の適用が成功しました。サーバーのテストは**9,311件・失敗0・エラー0・スキップ27件**です。実行時には、8,978位置でキャッシュあり／なしの優先度、無効時のPaperの順序、概要・詳細・停止・force・サービス停止の表示、実際のTCPクライアントへのツールチップ情報、両GPUの再読み込みを確認しました。単独のベンチマーク用クラスパス生成も修正し、動作を確認しました。

試験用プラグインと実際のローカルTCPクライアント1人を使い、シード4729262の通常地形を毎回新規作成しました。描画・シミュレーション距離10、ヒープ16 GiB、チャンクワーカー4、RTX 3070＋GTX 1080、GPUの自動CPU退避を有効にしています。飛行状態のサーバープレイヤーを1tickあたり1.6ブロック進め、600tickを計測しました。**サーバー側で動かした合成試験であり、エリトラ操作やロケット花火を完全に再現するものではありません。** 計測前にビルドを完了し、ユーザーの別のプラグインは試験に含めていません。

両方とも600サンプルすべてで方向先読みが動作し、クライアントエラーなしで完走しました。更新側では、起動・待機・飛行を通じてAnti-XrayのGPU結果262件が採用されました。プレイヤー距離計算のGPU結果は0件で、状態確認時には両GPUのAnti-XrayがCPUへの一時退避中でした。GPU計算は発生していますが、サーバーの大部分の処理はCPUに残っています。

各1回の比較では最大値・p99が改善した一方、平均・p95は悪化しました。**全体の高速化、全構成でのCPU同等以上、今後のTPS低下が発生しないことは証明していません。** コードと設定を一緒に変えているため、個々の効果は分離できません。先行する試験は601サンプルを記録したため比較から除外しました。この更新では300人・Mob 3,000体の負荷試験を再実行していません。

[機械可読の比較記録](results/elytra-priority-smoke.json)には測定JAR・プラグインのハッシュと実行フォルダを記録します。生ログ、CSV、クライアントのパケット、正確な試験用ソースとバイナリは`C:/GPur-validation-20261007`に保持します。配布JARはGit情報の違いでハッシュが変わる場合があるため、再検証では測定JARを保持してください。
